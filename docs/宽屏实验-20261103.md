## 2. 实现（`experiments/tablet-wide/mobile.css`）

```css
@media (min-width: 1100px) and (pointer: coarse) {
  :root:not([data-dsh-adapt="off"]) .dshm-shell [data-conversation-scroll] {
    --dsh-composer-side-clearance: 0px;   /* 列与胶囊同宽；会话列 padding 32→16 */
    width: 100%; max-width: 720px; margin-inline: auto;
  }
  :root:not([data-dsh-adapt="off"]) .dshm-shell [data-composer-card] {
    width: 100%; max-width: 720px; margin-inline: auto;
  }
}
```

- **三重门**：`.dshm-shell`（dedicated 硬守卫）→ `≥1100px` 粗指针 → opt-out。
- **必须写 `width:100%`**：`[data-conversation-scroll]` 是 flex 列的 `flex:1` 子项，
  只给 `max-width` + `margin-inline:auto` 会把 auto 宽度收缩成 fit-content（实测 720 → ~396）。
- **clearance 必须设在 `[data-conversation-scroll]`**：宿主把变量定义在更内层的 `.wSkVaW_body`，
  设在 `.dshm-shell` 会被覆盖（实测胶囊仍 683、正文仍 651）。
- 归零 clearance 后会话列 padding 从 32px 降到 16px：720−32=688 ≥ 680，**正文不会被收窄**。
- **侧栏不动**：dsh-mobile ≥900px 本来就是静态 grid 列（340/56px），实验不重写。
- **opt-out**：`html[data-dsh-adapt="off"]` 后全部规则不命中。该属性同时是宿主 0.8.1
  面板地板的门阀（`lib/mobile-layout.js:507`），所以是「本实验与宿主地板一起关」；
  只关实验请停用扩展。实验自身没有面板状态门阀（排版作用于会话列，与面板开关无关）。

## 3. 验证（lab）

```bash
node experiments/tablet-wide/probe.mjs            # 默认 ../../dsh-ui-lab
```

探针依次跑 1363×860 / 909×1314 / 834×1194（<1100）/ 1280×800（精指针），
打开一个**真实已有会话**（只做导航），测量会话列 / composer / 侧栏 / 首条消息，
注入 `mobile.css` 后再测，再设 `data-dsh-adapt="off"` 验证回落，并保存
before / after / opted-out 三张截图。2026-11-04 结果（**17/17 PASS**）：

| 场景 | 会话列（前→后） | composer（前→后） | 正文列 | 侧栏 | 判定 |
|---|---|---|---|---|---|
| 1363×860 | 1021 @340 → **720 @491.5** | 712 @492 → **715 @491.5** | 680→680 | 340 | 居中定宽 + 胶囊贴齐 |
| 1363×860 opt-out | 720 → 1021 | 715 → 712 | 680 | 340 | 回落 |
| 909×1314 | 567 → 567 | 530 → 530 | 498 → 498 | 340 | 规则不命中，完全不变 |
| 834×1194（<1100） | 776 → 776 | 712 → 712 | — | 56 | 规则不命中 |
| 1280×800（精指针） | 938 → 938 | 712 → 712 | 680 | 340 | 桌面零改动 |
| 非 dedicated 合成页（1363，粗指针） | 1023 → 1023 | 712 → 712 | — | — | 守卫生效 |

- **composer 715 vs 720**：headless Chromium 的经典滚动条占 5px，`width:100%` 只能拿到
  715；真机 overlay 滚动条预期 720。**真实会话的真机 720 证据仍待 device-tester 补**。
- 截图：`experiments/tablet-wide/shots/1363x860-{before,after,opted-out}.png`、
  `909x1314-{before,after,opted-out}.png`；原始数值 `shots/measurements.json`
  （含 `hostOverlay` / `nonDedicated` 记录）。
- ui-lab 0.2.1 没有 1363/909 的 profile，所以用上面的探针；它支持的 834 平板只能验证「<1100 不生效」：

## 4. t24 复核修复（F1 / F2）

- **F1 探针可复跑**：
  - 909 的「opt-out 回落」不再有 2px 滚动条槽位问题——1100 作用域下 909 规则不命中，
    before/after/opt-out 完全一致；「不变」类断言容差同时放宽到 **±3px**（滚动条槽位显式容错）。

    **屏蔽该请求**并把 `hostOverlay:{exists,blocked}` 写进 `measurements.json`，不把整屏文本拍进截图；
    本次运行时该文件不存在（`exists:false`）。
  - 909 重新保存 before / after / opted-out 三张截图（此前只有两张，且旧图可能被浮层污染）。
- **F2 作用域硬守卫**：
  - CSS 全部挂在 `.dshm-shell` 下（0.8.1 的稳定外壳标记）；媒体查询同步收窄到 `min-width:1100px`。
  - 探针新增**非 dedicated 反例**：无 `.dshm-shell` 的合成页在 1363 粗指针下注入同一份 CSS，
    会话列/胶囊前后完全一致（`nonDedicated.applied:false`）。

## 5. 与 dsh-go 的边界

- 只借鉴设计意图（侧栏常驻 / 内容居中 / composer 胶囊）；**没有**复制 dsh-go 的代码、类名、
  样式表或截图素材；dsh-go 为 AGPL/品牌保留，本实验全部独立编写。
- dsh-go 的「键盘弹出不挤」没有在本实验验证：headless 无法复现软键盘，真机需人工复测。

## 6. 未验证 / 风险

1. 真机平板（iOS/Android WebView）：safe-area、惯性滚动、软键盘都未测；
   composer 真机 720 的「真实会话」证据待 device-tester 补（lab 715 是 headless 滚动条差）。
2. 浮动控件（鲸鱼/用量气泡）在宽屏留白区仍可见；`floaters` 只负责面板让位，不处理留白区遮挡。
3. 依赖 `.dshm-shell` / `[data-conversation-scroll]` / `[data-composer-card]` /
   `--dsh-composer-side-clearance`；宿主改标记/变量即失效（实验接受）。
4. 正文列仍是宿主 680px；若要 720 正文需另改 `--dsh-chat-content-width` 并复测。
