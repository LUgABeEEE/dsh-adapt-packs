## 1. F1：轨道与 drawerToggle 的宽度

### 决定：选 (a) 补 `min-width:44`，并把 drawerToggle 一并纳入

t17 真机复测（0.8.1 平板，14:07 包）给出修前数字：

| 控件 | 旧包 12:46 | 新包 14:07 | 判断 |
|---|---|---|---|
| treeitem 会话 | 32px | **44px** | 已修好 |
| treeitem 项目 | 34px | **44px** | 已修好 |
| 折叠轨道 icon | 36×36 | **36×44** | 宽仍 36 → 本项 |
| drawerToggle 收起 | 28×28 | **28×44** | 宽仍 28 → 本项 |
| drawerToggle 展开 | 36×36 | **36×44** | 宽仍 36 → 本项 |

实现（`packs/shell-chrome/mobile.css`）：

```css
:root:not([data-dsh-adapt="off"]) .dshm-drawer [data-slot="sidebar"] :where(button, [role="button"], a) {
  min-height: 44px !important;
  min-width: 44px !important;
}
```

- 为什么安全：`min-width` **只抬不压**。展开/停靠态的行式按钮本来就是 280/312/320px，不受影响
  （t15 提醒的正是不要把这些改窄）；真正变宽的只有图标类控件（轨道 icon、drawerToggle、行内 rowActions）。
- 56px 轨道放得下 44px（每侧余 6px）；fixture 里轨道按钮修后为 44×44，无裁切。
- 没有按 `data-open` 分状态：两种状态都需要（收起 28×28、展开 36×36 都要抬）。

### 判据（`tools/check-pack.mjs`）

- fixture 增加 `drawerToggle`（`[data-fixture="drawer-toggle"]`，收起 28×28 / 展开 36×36，模拟 t17 数字）；
  它从通用 `sidebarButtons` 中排除，单独测量。
- 基线：rail 宽高都必须 <44；drawerToggle 两种状态的宽高都必须 <44；docked 行高度 <44。
- 断言：`runtime.shell.rail`、`runtime.shell.drawerToggle`、`runtime.shell.dockedRows` 都检查**宽与高**
  （`min(width,height) ≥ 44−ε`，与同文件其它判据一致）；
  `checkOptOut` / `checkDesktop` 也逐项比较 rail、drawerToggle（两种状态）、docked 行。
- 红色回归：`test/checkpack-regression.test.mjs` 新增「把 `min-width:44` 改回 36」→
  `runtime.shell.rail` 必须 FAIL（消息带 `36×44`），`runtime.shell.drawerToggle` 同时 FAIL。

## 2. F2 / BUG-02：逐类计数与定向开关试验

### 2.1 真实页逐类计数（390×844，0.8.1，Plugins settings）

| 类别 | 总数 | <44 | 典型 |
|---|---|---|---|
| `button[role="switch"]` | **41** | **41** | 36×20，`min-height:auto` |
| 其它 button / `[role="button"]` | 53 | 0 | 宿主地板 44 |
| `a` / 表单 / 其它 | 0 / 0 / 0 | 0 | — |
| 合计 | **94** | **41** | 与 t12 一致 |

方法：读-only Playwright（dsh-ui-lab 配对缓存）打开 0.8.1 专用页 → 侧栏 `Plugins`（列表页），
遍历 `[data-slot="main"]` 的可见控件，按 role/tag 分类并读 `getBoundingClientRect` / `computedStyle`。
数字已写进 `catalog.json` 的 `core-panel.evidence.missing`。

### 2.2 定向 `button[role="switch"]` 透明命中层试验

fixture 复刻 DSH 核心 `Switch`（`@deepseek-ai/dsh-client-ui-primitives`：`lib/index.js:3463-3478`、
`Switch.module.css` 36×20、轨道=按钮背景、旋钮=子 `span` 16×16），并加一个「用 `::after` 画旋钮」的
第三方开关作风险对照。规则：

```css
:root:not([data-dsh-adapt="off"]) [data-slot="main"] button[role="switch"] { position: relative !important; }
:root:not([data-dsh-adapt="off"]) [data-slot="main"] button[role="switch"]::after {
  content: ""; position: absolute; inset: -12px; background: transparent;
}
```

| 观测 | 核心开关 | 第三方开关（`::after` 旋钮） |
|---|---|---|
| 命中 | 修前 ±20/24px 落 `DIV.row`；修后四点全部命中 `switch` | — |
| 视觉 | 36×20、旋钮 16×16 不变（`visualUnchanged: true`） | 旋钮 `::after` 被改成 `top/left:-12px`、`background:transparent` → **视觉破坏** |
| 点击 | 扩展边缘点 `click()` → `aria-checked` false → **true** | — |
| opt-out | 四点回到 `DIV.row`，盒子仍 36×20 | — |

结论：**技术可行，但不作为通配规则发布**——`core-panel` 的 `target:null` 会命中所有第三方开关，
覆盖它们用伪元素画的轨道/旋钮。这是**我们当前规则下的空白**（不是「只能上游修」）：
外部适配层要在不点名私有类名的前提下做，需要宿主给出稳定标记。
上游最小修复：① primitive 内部加透明命中层（该组件无自有伪元素，天然安全）；
② 设置页行/开关加 `data-dsh-*` 稳定标记；③ 修卡片标题按钮与开关的层级重叠。

完整证据见 `docs/修复-适配矩阵-20261102.md` §3。
